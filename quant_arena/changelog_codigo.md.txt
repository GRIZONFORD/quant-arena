## [v0.1.0] — 2026-05-25 — Arquitectura Base + Módulos Métricas y Juez

### Estado del diseño
Inicialización del framework. Arquitectura definida en 6 módulos; implementación
completa de `core`, `metricas` y `juez`. Los módulos `backtesting`, `zoo` y
`resultados` tienen esqueletos funcionales.

---

### Archivos creados

#### `quant_arena/core/abstracciones.py`
- `MetricasResultado` — Dataclass DTO con 7 KPIs institucionales (sharpe, sortino,
  max_drawdown, calmar, information_ratio, alpha_tstat, turnover).
- `AbstractMetricas` — Interfaz ABC para calculadoras de métricas.
- `AbstractStrategy` — Interfaz ABC para sub-estrategias del Zoo.
- `AbstractJuez` — Interfaz ABC para el Juez algorítmico.

#### `quant_arena/metricas/performance_metrics.py`
- `PerformanceMetrics(AbstractMetricas)` — Implementación vectorizada completa.
  - `sharpe_ratio()` — Sharpe anualizado con exceso sobre RFR.
  - `sortino_ratio()` — Downside deviation con MAR = RFR diaria.
  - `max_drawdown()` — Vectorizado via `cummax` de Pandas.
  - `calmar_ratio()` — CAGR / |MDD|.
  - `information_ratio()` — E[r_activo] / TE * sqrt(252).
  - `alpha_tstat()` — OLS vectorizado con `pinv` (Jensen alpha t-stat).
  - `turnover()` — Rotación media diaria del portafolio.
  - `calcular_todas()` — Punto de entrada unificado -> `MetricasResultado`.
  - `calcular_rolling()` — Cualquier métrica en ventana rodante causal.

#### `quant_arena/juez/ttt_juez.py`
- `TTTJuez(AbstractJuez)` — Adaptador de `TrueSkillThroughTime` (Landfried, 2024).
  - `registrar_periodo()` — Mapea ranking por KPI a `composition` de TTT.
  - `actualizar()` — Ejecuta `History.convergence(epsilon, iterations)`.
  - `habilidades_latentes()` — Extrae `(mu, sigma)` de `learning_curves()`.
  - `pesos_asignacion()` — 3 métodos: `mu/sigma`, `mu` bruto, `softmax`.
  - `curvas_aprendizaje()` — Trayectoria temporal completa para visualización.
  - `log_evidencia()` — `History.log_evidence()` para selección de hiperparámetros.
  - `snapshot_estado()` — DataFrame de estado posterior (logging/monitoreo).
  - `exportar_curvas_df()` — Long-format para matplotlib/seaborn.

#### `quant_arena/zoo/base_estrategia.py`
- `RegistroZoo` — Registro singleton con decorador `@RegistroZoo.registrar`.
- `MomentumTransversal(AbstractStrategy)` — Estrategia de referencia (12-1m).

---

### Decisiones de diseño

| Decisión | Justificación |
|---|---|
| `AbstractMetricas` stateless | Facilita testeo unitario y reutilización en rolling windows |
| `MetricasResultado` como dataclass | Tipado estricto + serialización `asdict()` sin overhead |
| `TTTJuez` con flag `_dirty` | Evita recomputar convergencia cuando no hay nuevos datos |
| `modo_causal_estricto` en `TTTJuez` | Distingue modo backtesting (filtrado) de análisis histórico (suavizado) |
| `RegistroZoo` con decorador | Desacopla el Motor del Zoo; nuevas estrategias no modifican infraestructura |
| `pinv` en `alpha_tstat` | Estabilidad numérica ante benchmarks con baja varianza en la ventana |
| `times` en `History` (días desde época) | Permite a TTT modelar aceleración de cambio de régimen entre períodos |
| Pesos TTT: `mu/sigma` como default | Análogo bayesiano del Sharpe Ratio — pondera señal vs. incertidumbre |

---

### Flujo de datos (DAG causal)

```
Zoo.generar_señales(datos, t-1)
    -> Backtesting.Motor: retornos período [t-W, t-1]
        -> PerformanceMetrics.calcular_todas()
            -> MetricasResultado {sharpe, sortino, ...}
                -> TTTJuez.registrar_periodo(metricas, tiempo=t-1)
                    -> TTTJuez.actualizar()  [solo con datos hasta t-1]
                        -> pesos_asignacion()
                            -> Zoo (siguiente período t)
```

---

### API de TrueSkillThroughTime usada (v0.1.0)

```python
# Inicialización (ref: ejemplo ATP en README oficial)
h = History(composition=composition, times=days, sigma=1.6, gamma=0.036)

# Inferencia EP
h.convergence(epsilon=0.01, iterations=10)

# Extracción de posteriors
lc = h.learning_curves()  # {agente: [(t, Gaussian(mu, sigma)), ...]}

# Comparación de modelos
evidencia = h.log_evidence()
```

## [v0.2.0] — 2026-05-25 — Filtro de Kalman + Zoo Infrastructure + MomentumStrategy

### Archivos creados / modificados

#### `quant_arena/metricas/filtros.py` (NUEVO)
- `_EstadoKalman` — NamedTuple interno para estado `(x, P)`.
- `KalmanSignalFilter` — Filtro de Kalman escalar, causal y NaN-safe.
  - `filtrar(serie, x0)` — Algoritmo exacto secuencial. NaN = paso predict-only.
  - `filtrar_con_varianza(serie)` — Retorna `(x_filtrado, P_t)` para bandas de confianza.
  - `filtrar_rapido(serie)` — Aproximación EWMA vectorizada usando `K*` estacionario.
  - `filtrar_dataframe(df, rapido)` — Aplica el filtro por columna.
  - `filtrar_historial_metricas(historial)` — Interfaz directa con salida del Motor.
  - `ganancia_estacionaria` — Propiedad: solución analítica de Riccati escalar.
  - `periodos_convergencia` — Estimación de períodos para alcanzar el 99% de K*.

#### `quant_arena/zoo/base_estrategia.py` (REESCRITO)
- `normalizar_pesos(señales, long_only, max_peso)` — Función módulo-nivel vectorizada;
  truncamiento iterativo para restricción max_peso por activo.
- `señales_a_binario(scores, top_n, ascending)` — Máscara top-N via `rank()` sin sort.
- `RegistroZoo` — Mejorado: guard de nombre duplicado, `listar_con_descripcion()`,
  `autodescubrir(paquete)` para discovery automático via `pkgutil`.
- `ConfigEstrategia` — Dataclass declarativa de instanciación de estrategias.
- `ZooManager` — Fachada del Motor sobre el conjunto activo de instancias:
  `agregar()`, `agregar_desde_config()`, `generar_señales_todas()`,
  `calcular_retornos_todos()`.
- **Eliminado**: `MomentumTransversal` (movido a `zoo/estrategias/ejemplo_momentum.py`).

#### `quant_arena/zoo/estrategias/ejemplo_momentum.py` (NUEVO)
- `MomentumStrategy(AbstractStrategy)` — Registrada como `'momentum_126d'`.
  - Señal: `precio(t) / precio(t-ventana) - 1` (vectorizado, un slice + división).
  - Selección top N via `señales_a_binario()` (sin sort explícito, O(N log N) rank).
  - 3 esquemas de pesos: `'equal'`, `'proporcional'` (∝ señal), `'rank'` (∝ 1/rango).
  - `max_peso_activo`: límite de concentración con truncamiento iterativo.
  - `calcular_retornos()`: dot product vectorizado `(pesos * retornos).sum(axis=1)`.

---

### Decisiones de diseño adicionales

| Decisión | Justificación |
|---|---|
| Loop secuencial en `KalmanSignalFilter.filtrar()` | El filtro de Kalman es inherentemente recursivo; el loop itera sobre el eje temporal, no sobre activos/filas de precio |
| `filtrar_rapido()` como EWMA vectorizado | Para series largas (> 1000 obs.), K* converge rápidamente; EWMA via `pd.ewm` es O(N) sin GIL |
| `normalizar_pesos` como función de módulo | Utilidad compartida por múltiples estrategias; no es responsabilidad de `AbstractStrategy` (SRP) |
| `ZooManager.generar_señales_todas()` filtra datos antes de delegar | Doble garantía causal: el Manager refuerza el contrato de `AbstractStrategy` |
| `señales_a_binario()` usa `rank()` | Evita `sort_values()` que es O(N log N) con overhead de reordenamiento; `rank()` también O(N log N) pero sin copia del índice |
| `ConfigEstrategia` como dataclass | Separación configuración/instanciación; el Motor puede leer configs de YAML/JSON sin importar clases concretas |
| Guard de nombre duplicado en `RegistroZoo.registrar()` | Detecta colisiones de nombres en tiempo de importación, no en runtime |

## [v0.3.0] — 2026-05-25 — Motor de Backtesting Walk-Forward

### Archivos creados / modificados

**`BacktestEngine`** (clase principal):

Flujo causal por rebalanceo `t_k`:
1. `_retornos_periodo()` — retornos `(t_{k-1}, t_k]` con pesos de `t_{k-1}` (dot product vectorizado)
2. `calcular_rolling()` — último valor de la ventana rodante = señal ruidosa en `t_k`
3. `KalmanSignalFilter.filtrar()` — suaviza el historial acumulado de observaciones hasta `t_k`
4. `TTTJuez.registrar_periodo()` + `.actualizar()` — inferencia EP con señal limpia
5. `generar_señales_todas(datos, t_k)` — nuevos pesos para el período siguiente

| Método | Responsabilidad |
|---|---|
| `ejecutar_walk_forward(inicio, fin, frecuencia)` | Orquesta el loop completo |
| `_generar_fechas_rebalanceo()` | Snap a días de trading disponibles; soporta `int` y `str` offset Pandas |
| `_retornos_periodo()` | Retornos incrementales con pct_change vectorizado, NaN-safe |
| `_ensamblar_meta()` | Aplica pesos TTT por período (causal) para construir retornos del meta-portafolio |
| `_consolidar()` | Ensambla todas las estructuras acumuladas en `ResultadoBacktest` |

#### `quant_arena/backtesting/__init__.py` (ACTUALIZADO)
- Exporta `BacktestEngine` y `ResultadoBacktest`.

---

### Invariantes de causalidad del Motor

```
pesos_vigentes[nombre] en t_k  ←  datos[0:t_{k-1}]   (señales del rebalanceo anterior)
retornos_periodo[(t_{k-1}, t_k]]  ←  pesos_vigentes × precios[(t_{k-1}, t_k]]
metricas_rolling[t_k]  ←  retornos_acumulados[0:t_k]
kalman_filtrado[t_k]  ←  metricas_rolling[0:t_k]      (filtro causal elemento a elemento)
TTT_composition[t_k]  ←  kalman_filtrado[0:t_k]
pesos_juez[t_k]  ←  TTT.habilidades_latentes()         (posterior tras observar hasta t_k)
pesos_siguiente_período  ←  generar_señales(datos[0:t_k])   ← usa t_k como corte duro
```

### Decisiones de diseño adicionales

| Decisión | Justificación |
|---|---|
| `listas_ret` como `List[Tuple[Timestamp, float]]` | Append O(1) por cada día; construcción de Series solo al calcular métricas |
| `pesos_juez_actuales` inicializado como equal-weight | Neutral durante el warm-up; evita sesgo hacia cualquier estrategia antes de que TTT tenga datos |
| `_ensamblar_meta()` como método estático | No accede a `self._datos`; facilita testeo unitario aislado |
| `frecuencia` acepta `int` y `str` | `int` para frecuencias fijas en días hábiles; `str` para alineación con fin de mes/trimestre |
| Catch-all en `TTTJuez.actualizar()` | Dependencia externa (trueskillthroughtime); el Motor sigue ejecutando con pesos previos si falla |
| `pesos_portafolio` almacena snapshots (no serie diaria) | Ahorra memoria; `pesos_portafolio_diarios()` expande con ffill cuando se necesita para visualización |

## [v1.1.0] — 2026-05-25 — Calibración Empírica de Bayes (Módulo `calibracion/`)

### Estado del diseño
Primer módulo de la fase de optimización. Implementa la calibración automática
de los hiperparámetros `sigma` y `gamma` del modelo TTT maximizando la
log-evidencia marginal `log p(D | σ, γ)` via `scipy.optimize.minimize`.

---

### Archivos creados / modificados

#### `quant_arena/juez/ttt_juez.py` (MODIFICADO)
- `exportar_historial()` — nuevo método público que retorna copias defensivas de
  `_composition` y `_times` para consumo por `OptimizadorTTT` sin exponer referencias
  mutables al estado interno del Juez.
  - `_composition` → `copy.deepcopy`: estructura anidada `List[List[List[str]]]`; copia
    superficial dejaría sub-listas compartidas entre original y consumidor.
  - `_times` → `list()`: suficiente porque `float` es inmutable en Python.
  - `AbstractJuez` **no fue modificado**: el método es concreto adicional en `TTTJuez`.

#### `quant_arena/calibracion/__init__.py` (NUEVO)
- Exporta `OptimizadorTTT`.

#### `quant_arena/calibracion/optimizador.py` (NUEVO — ~180 líneas)

**`OptimizadorTTT`**:

| Método | Descripción |
|---|---|
| `_evaluar_log_evidencia(log_params, composition, times)` | Función escalar: instancia `History` temporal, ejecuta EP, retorna `log p(D | σ, γ)`. Captura todas las excepciones → `_LOG_EV_FALLBACK = -1e9`. |
| `calibrar(composition, times, bounds)` | API pública. Minimiza `−log_evidencia` con `L-BFGS-B` en espacio logarítmico. Retorna `{'sigma_optimo', 'gamma_optimo', 'log_evidencia_maxima'}`. |

Principio matemático:

$$(\sigma^*, \gamma^*) = \arg\max_{\sigma,\gamma>0} \log p(\mathcal{D} \mid \sigma, \gamma)$$

implementado como `min_θ −log p(D | eᶿ⁰, eᶿ¹)` con `θ = (log σ, log γ) ∈ ℝ²`.

|---|---|

#### `quant_arena/docs/superpowers/specs/2026-05-25-calibracion-ttt-design.md` (NUEVO)
- Design spec formal con decisiones D1–D5 y flujo de uso canónico.

---

### Decisiones de diseño

| Decisión | Justificación |
|---|---|
| `exportar_historial()` como puente DRY | Evita duplicar la lógica ranking→composition de `registrar_periodo()` en el optimizador |
| `copy.deepcopy(_composition)` + `list(_times)` | Copia superficial sobre `List[List[List[str]]]` deja sub-listas compartidas; `float` es inmutable → `list()` suficiente |
| Optimización en espacio log `θ = (log σ, log γ)` | Garantiza σ, γ > 0 sin restricciones de desigualdad; mejora estabilidad numérica de L-BFGS-B en dominios semi-infinitos |
| `epsilon_ep=0.1`, `max_iter_ep=5` durante búsqueda | Reduce ~6× el costo por evaluación; la dirección del gradiente EP es suficientemente precisa con tolerancia suelta |
| `_LOG_EV_FALLBACK = -1e9` como sentinela | Valor finito que scipy puede manejar; indica puntos degenerados sin lanzar excepciones que abortarían la minimización |
| `History` temporal por evaluación | `History` es stateful (acumula mensajes EP); crear una instancia nueva por llamada garantiza independencia entre evaluaciones |
| `np.clip` post-optimización sobre `exp(x)` | Garantía adicional de bounds incluso si L-BFGS-B devuelve un punto marginalmente fuera por error de punto flotante |

---

### Flujo de uso canónico

```python
composition, times = juez.exportar_historial()
opt = OptimizadorTTT(sigma_inicial=1.6, gamma_inicial=0.036)
params = opt.calibrar(composition, times)
juez_v2 = TTTJuez(sigma=params['sigma_optimo'], gamma=params['gamma_optimo'])
```
